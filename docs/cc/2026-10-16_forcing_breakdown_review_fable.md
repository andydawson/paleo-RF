# Forcing by month and latitude (script 10): review by Fable (with reconciliation)

**Fable review: forcing breakdown by month and latitude (branch forcing-breakdown, commits ee50abc, df9a7e9, d766260)**

**Verdict.** Mergeable as a decomposition of script 9 (arithmetic correct, identity holds in general); it does not yet answer the snow question as posed, because the variant it breaks down is dominated by ice-sheet retreat, which the calibration's missing snow term does not touch; two should-fixes (documentation of the columns; the vegetation-only run) and a handful of nits.

**Benefit.** From outputs already produced, Andria can see which months and latitudes each period's headline forcing comes from, so the paper's caveat about past snow can be bounded and the planned snow sensitivity test aimed at the months and bands that matter, with no new modelling.

**Hand check.** Two cells, one period of two slice-pairs, two months, CACK-like missing month. Cell A: area 2, lat 35.5 (band 30-40 N); cell B: area 1, lat 72.5 (band 70-74 N). Per-pair forcing: A jan 1, 2; A feb -1, 0.5; B jan NA, NA (polar night); B feb 4, 2. E = Earth's area.
- Script 9 (`scripts/9_forcing_barplot.R:148-157`): A5 sums: A jan 3, A feb -0.5, B jan NA, B feb 6. A6 means over months with a value: A 1.25 (n=2), B 6 (n=1). A8: global_equiv = (1.25×2 + 6×1)/E = 8.5/E.
- Script 10 (`scripts/10_forcing_breakdown.R:193-204`): months_with_value A=2, B=1. jan/30-40: global_equiv_month 6/E, contribution 3×2/2/E = 3/E, band_mean 3, area 2. feb/30-40: -1/E, -0.5/E, -0.5, 2. jan/70-74: 0, 0, NaN, 1. feb/70-74: 6/E, 6/E, 6, 1. Sum of contribution_to_annual = (3 - 0.5 + 0 + 6)/E = 8.5/E. Agrees.
- Algebra, general case: script 9's per-cell value is Σ_m rf_m / n_cell with n_cell = number of non-NA months (mean na.rm=TRUE), and a cell with n_cell = 0 is NaN and dropped by `sum(na.rm=TRUE)`. Script 10's contribution per (month, band) is Σ_cells rf_m·area/n_cell/E; summed over months and bands it is Σ_cells (area/E)·Σ_m rf_m/n_cell, the same expression; a cell with n_cell = 0 gives NA/0 = NA, dropped by `na.rm=TRUE`. A pair that is NA makes the whole month NA in both scripts (same `na.rm=FALSE` at the first summarise). Cells removed by the completeness filter are removed before both, by the same function. The identity needs only that `area` and `lat` are constant within a cell, which they are (one row per cell-month-pair from script 8). So the identity is exact in general, not only on this data.
- Against the run: HadGEM3 8-10 ka, sum of the six band figures in the log (-0.0023-0.0343+0.0426+0.2209+0.0693+0.0065) = 0.3027; sum of the twelve month figures = 0.3028; anchor `tests/anchors/interp-forcing-2026-10-08/forcing_by_period.csv` global_equiv = 0.302796. Band areas in the CSV sum to 1.92238e13 = the anchor's area_m2. CACK jan 27-30 N: global_equiv_month / contribution = 12.000 (all cells have 12 months); CACK jan 70-74 N: ratio 11.0 (December missing north of 69 N, A6); HadGEM3 dec 70-74 N is 0,0,0 (kernel stored as 0 in polar night, A6), CACK dec 70-74 N is 0,0,NA. All as the code implies.
- Sign: unchanged from script 8 (`8_radiative.R:99-104`, brighter surface negative); 8-10 ka ice retreat positive in summer at 50-70 N, as expected.

**Findings.** Worst first.

1. Should-fix (scientific scope, not code). `scripts/10_forcing_breakdown.R:117-122` and the packet's purpose. The variant broken down is `veg_ice_thresh`, whose early-Holocene signal is ice-sheet retreat (8-10 ka: 0.22 of 0.30 W/m2 in 50-60 N, concentrated in May-Aug). The ice albedo comes from `data/albedo_glacier_monthly.csv`, fixed per month, not from the calibration; the "no snow term in the calibration" assumption bears only on the vegetation term. Consequence: a reader (or Andria) would attribute the summer 50-70 N peak to the snow question when it is ice. Evidence: the log's band and month tables; config comment at `configs/legacy_config.R:120-123`. Verification: run scripts 9 and 10 with a config copy whose `variant` is `veg_thresh` (drops ice cells, as A2 notes) or `veg_part` (complete), no code change needed; the header should state that the snow question is read from the vegetation-only run, and the ice-dominated periods from this one.

2. Should-fix (documentation). `scripts/10_forcing_breakdown.R:46-56` header. (a) `global_equiv_month` summed over months gives 12× script 9's annual figure (n× for cells with n months); the header does not say so, and a reader summing the CSV's first value column will get a number 12 times the bar. (b) `band_mean` is the mean over the band's cells *with a value* in that month, so `band_mean × area_m2 / E ≠ global_equiv_month` where CACK has missing months (CACK jan 70-74 N: 0.815 of the band's area has a value); `area_m2` counts every cell, with or without a value. One sentence each.

3. Should-fix (robustness of a setting). `scripts/10_forcing_breakdown.R:181` with `R/config_schema.R:154` (range 1-90). `seq(ceiling(lat_min/bw)*bw, lat_max, by = bw)` errors ("wrong sign in 'by'") when the first multiple exceeds lat_max: for the 27-74 N domain any width from 75 to 90, all admitted by the schema. And the schema admits fractional widths (e.g. 2.5), which put cell centres (x.5) exactly on edges; with `cut(right = TRUE)` such a cell goes to the band *below*, so a cell spanning 32-33 N is labelled 30-32.5 N. Consequence: a legal config stops the script or mislabels bands. Fix: require a whole number (`check_whole(v, c(1, 90))` exists at `config_schema.R:105`) and build the edges as `multiples = bw * seq_len(floor(lat_max/bw)); multiples[multiples > lat_min]`, which is empty rather than an error when no multiple falls inside. Test: widths 1, 3, 7, 47, 74, 90 on the 27-74 domain.
