1. **Should-fix (verification). The model-7 tool does not establish that it compares like with like.** `tools/check_model7_convergence.R:33-40, 52-54`. 2. **Should-fix (run plan). No guard against fitting a month with no, or too little, support.** `scripts/4_calibration_model.R:37-46`. With `statistic = "snowy"` the summer columns are mostly NA; `na.omit` then hands `bam` few or zero rows, and the run stops with mgcv's message only when it reaches that month, after hours on the others; a month with a few hundred rows fits 750 basis functions without stopping. Fix: before the first fit, `counts = colSums(!is.na(cal_interp_data[months]))`, print it, stop if any month is below the largest model's coefficient count (about 750). Which months the snowy run should fit is Chris's call (question below); the per-month snowy counts are not in the build report (it gives all-days and snow-free only).

3. **Should-fix (records/science). The run record counts cells with a value, which hides how thin the main version's winter support is.** `scripts/2_calibration_lct_bluesky.R:213-217`. Evidence: `data/albedo_modis_cells.csv:13765`, cell (−127.5, 50.5), December: full_75 has a value (so it counts as a fitting cell) from 9.3 % of its land pixels and 0.42 pixel-days per pixel, while any_75 has 91 % and 15.8 days. Full BRDF inversions are scarce in winter, so "1,416 December cells" overstates the support behind the December fit; the `_coverage` and `_days` columns measure it and nothing reads them. Fix, within the "counts in the run record" decision: per month, the median and 10th percentile of `<version>_coverage` and `_days` over the cells with a value (four numbers a month, from the table already in memory). Consequence for the paper: the winter sensitivity (November-February, no sun rule) and the snow-free run cannot be interpreted without this. The related question (a minimum coverage, or weights) goes to Andria; the code applies no minimum, by Chris's decision for the all-days value.
